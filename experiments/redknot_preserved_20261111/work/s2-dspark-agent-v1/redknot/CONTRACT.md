# S2 natural-document adapter

This is an independent adapter around the copied S1.2 implementation. It does not pad or split inputs into ten artificial blocks, change first-three-layer execution, tail128/halo128 policy, source2, Engram, mHC, decoder math, or the group17 native capacity.

`plan_request(input_ids, documents, scope, bank_budget_bytes=cap, session_certificate=controller.session_certificate, **controller.resident_bank_state())` accepts exact spans in the final rendered prompt. The service must supply those spans from its renderer/token alignment; the adapter does not infer source identity from filenames or text substring search. Scope is the model, execution and tokenizer SHA-256 identity. Identical token content at different spans is one bank key with multiple positional occurrences. A changed token sequence is a miss, even when its path is unchanged.

Blocks shorter than 256 tokens stay in the prompt as fully recomputed nondocument rows. With no eligible block, or when any group17 deep batch would exceed the unchanged 8192 selected-row capacity, the whole request explicitly falls back to Full. Record requested arm `s2`, effective arm `full` and the reason; do not drop that request from S2 latency, QPS or accuracy.

The class returned by `adapted_controller_class()` privately clones the existing controller inheritance hierarchy. Operator/forward/finish bytecode stays identical. Document admission is rebound in private globals, and exactly one guard in each of two private reset methods is replaced by explicit S2 admission methods. The guarded statements are identified by exact frozen messages and the adapter refuses any unexpected rewrite count. Tensor operations, row construction and original modules/classes are untouched. Its default capture is memory-only using the original cache's existing optional serialization contract. `set_cache_output_dir(path)` remains available when explicit raw payload evidence is required.

Service sequence per logical S2 request:

1. Start the request timer at HTTP admission, before queueing, rendering, planning or cache lookup. Broadcast the exact request to all eight workers.
2. Build the plan and call rank-zero `begin_request(plan, request_id=...)`. This preserves immutable document tensors and process-native qualification, but clears the previous prompt's sparse/system qualification and global workspace.
3. For each returned unique missing key, all eight ranks execute the original independent capture of that exact token document. A complete hit requires all 37 SWA halo and three global entries, matching model/execution/tokenizer scope, lengths and unchanged tensor versions. Partial entries fail closed.
4. Call `prepare_case` on the admitted effective documents. Before a session certificate exists, the strict qualification path runs fresh same-prompt dense group1 and group17 comparison and binds all original-chunk/40-layer outputs, four mHC fields, source2 and bounded generation to this request and bank. After issuing a valid S2 session certificate, supported requests use the explicit new session admission path; they do not repeat dense generation. Old RAG proofs never admit S2.
5. Configure/reset the admitted group17 request, broadcast its schedule, gather all eight installation acknowledgements, install the unchanged idle candidate, and execute serial native collective stepping. Finish controller, worker and candidate reports before another request begins.
6. A Full fallback skips capture and sparse preparation, uses system-disabled group1/native reset with no cached document spans, and never enables the idle candidate. The main Full arm uses an independent native process with no RedKnot hooks or bank.

Persistent tensors do not imply persistent request state. After native engine initialization, obtain actual free-memory bytes on all eight ranks, broadcast `uniform_bank_budget(free_bytes_by_rank) = min(4 GiB, min(all eight free-byte readings) // 5)`, and bind the readings and cap in the run manifest. This is a payload cap, not a claim to reserve allocator or temporary workspace bytes. Before every request, `resident_bank_state()` measures complete live tensor payload bytes; the plan adds the predicted unique misses. A missing budget or a projected overflow produces explicit Full fallback before capture. `begin_request` rejects stale resident inventories. There is no eviction and no retry that treats a partial capture as a hit. Record both predicted payload and actual retained bytes; allocation failures still fail the request rather than silently extending the memory budget.

## Measurement contract

- Request TTFT is first actual emitted model token timestamp minus HTTP admission timestamp. It includes queueing, rendering, tokenize/span alignment, misses, capture, fresh qualification, schedule/hook setup and prefill. A fake acknowledgement or buffered final response is not a first token.
- Request end-to-end latency ends after the actual final output/tool-call message is emitted; record natural stop, token count and failures. Agent task end-to-end additionally includes all tool calls, delegates, orchestration and evaluation-relevant completion.
- HTTP QPS is the number of fully completed admitted HTTP requests divided by the common measured wall-clock interval. Agent task throughput is completed tasks divided by its full wall-clock interval; report these separately. Record failed, fallback and truncated requests rather than removing them from the workload.
- Cold cache build wall time, hit/miss unique document count, reused bytes/tokens and retained bank bytes are separate counters. Primary cold/online results include build time; an explicitly labeled warm result must show the setup cost and cannot replace the cold result.
- Full and S2 use the same model/tokenizer, prompt renderer, generation/tool settings, task IDs, concurrency, hardware and deadline. Report actual native concurrency (initially serial EP8/DP8) separately from agent/delegate concurrency. No 8-way request throughput is implied by EP8/DP8.
- Official task accuracy comes from the official evaluator of each completed task. Same-policy numerical qualification does not establish equal Full/S2 accuracy. Counterfactual trace reuse is not an online model run or cache hit.

Only CPU admission tests exist for this new adapter. Real native all-rank initialization, natural-document numerical qualification, bounded bank memory and online HTTP integration still require actual S2 evidence before performance acceptance.

## Representative session certificate

`redknot/session.py` issues a new S2 certificate only after reading sealed fresh process/startup evidence, the actual all-eight-rank native/operator/mask/metadata receipts, and the real natural-source suite's dense/candidate phases. Each numerical case independently checks complete original-chunk/40-layer output/four-mHC fingerprints, source2 preservation, bounded natural-EOS generation, the actual group schedule and every rank's exercised idle bypass. The supported input, document-count, document-length and selected-group-row upper bounds are taken from those actual cases; unmatched geometry becomes an explicit Full-fallback plan.

The minimal suite is: a natural full source plus a short line; a different prefix containing the same resident source twice at different positions; multiple different complete source files spanning seventeen chunks plus a partial group; and a short-only native fallback. Actual candidate decode steps must be observed. `qualification_cases.rendered_requests` can use the real captured official agent `messages` and `tools` as its prefix; it adds no padding. The diagnostic corpus is cleared before official tasks, and the service verifies zero retained diagnostic bank bytes.

This certificate is representative implementation evidence, not a proof of numerical equivalence for every future prompt. Each request still checks its exact content IDs, offsets, scope, current bank versions, phase mapping, capacity and budget. No old `sparse_qualified` or `system_qualified` flag is set to pretend that the current prompt was numerically compared. Formal evidence explicitly reports `qualification_scope=representative_session`, its certificate SHA and `per_request_numeric_comparison=False`.

Session qualification is setup work. Record its actual time and include it in the whole experiment wall time; it is not repeated in each LLM request TTFT. Online cache misses and request preparation remain inside TTFT. Full fallback requests, failures and out-of-domain counts stay in the S2 arm's overall throughput and accuracy accounting.

## Three-arm comparison and actual prefix evidence

The requested comparison is Full with prefix reuse disabled, native PrefixReuse, and S2. Native prefix reuse is a different mechanism from S2's independent-document bank. Full must start every request with zero cached tokens and no retained blocks/forks; it has no RedKnot hooks. A PrefixReuse hit requires an exact token-prefix match to a live saved native state and actual skipped prefill rows. Prompt text similarity, SDK cache-control settings, or an application-written hit counter do not establish a KV hit.

The frozen native implementation exposes `scheduler.fork_seq`, which pins KV blocks and compressor state and clones writable state/tail blocks during scheduling. Its normal `add_request` path creates a fresh sequence and does not perform automatic prefix lookup. `finalize_seq` frees native ownership, so retaining a Python sequence object is insufficient. A reusable checkpoint must preserve the actual state at the claimed token boundary. Reducing `num_cached_tokens` on a later state does not roll back compressor state or the SWA ring and must not be used as an arbitrary longest-common-prefix restoration.

For qualification and each reported hit, retain source/target token hashes, the exact matched boundary, the state capture boundary, ownership/clone receipts and actual prefill query ranges. The frozen prefill scheduler reports `num_cached_tokens_gpu=0`, and `cached_hit_tokens` is an application-set field; neither is accepted as sole evidence. PrefixReuse must numerically match fresh Full on a small deterministic cold/hit/changed-prefix/miss suite before performance acceptance. Memory-cap misses and unsupported state boundaries remain measured misses.

The implemented baseline is labeled `Prefix(copy)`: it uses a read-only native-structure descriptor, captures raw KV blocks and the entire native state row at the same committed, 128-aligned prompt checkpoint, and later copies those bytes into a normally allocated native request. It does not hold native state slots or claim zero-copy/radix behavior. Extra prefill cuts, capture, lookup, eviction and restore costs remain in actual request/whole-run clocks. Prefix(copy) uses whole-snapshot LRU; S2's document bank does not evict. Report that policy difference and each arm's actual retained bytes.

`prefix_gate.audit_prefix_request` reconstructs contiguous actual prefill ranges from all eight worker reports. A hit must begin at the restored prefix boundary and compute exactly the remaining prompt rows; inactive ranks report no real rows. Qualification additionally binds the previously recorded source capture and verifies both raw KV and complete-state fingerprints before comparing all bounded generated IDs, text and stop reason with fresh Full. `source_snapshots` maps each snapshot ID to its original capture receipt and request IDs; an unbound restore cannot pass the numerical qualification. Explicit oversize skips are recorded separately and never counted as snapshots.

Official agent runs may produce different later requests in different arms. Report their actual task accuracy, task wall time, request counts, input/output tokens and throughput without calling different trajectories a same-request cache speedup. A separately labeled paired service diagnostic may submit identical recorded token requests in identical order to all three arms, keeping whole requests and sampling settings together. It does not supply new official agent accuracy or establish multi-agent online execution. Cache state starts cold under the same declared policy; construction, failed requests and fallback time stay in the observation window. The common time interval must include the last failed or unfinished admitted request, not stop at the last successful completion.
